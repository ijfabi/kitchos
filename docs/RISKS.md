# Risks and open issues

| ID    | Risk / issue                                                                                                                         | Impact | Mitigation / next step                                                                                         |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------ | ------ | -------------------------------------------------------------------------------------------------------------- |
| R-001 | Order placement is serialised per restaurant/day by the order-number counter row lock, and event production by the sequence row lock | Medium | Acceptable per store; measure with k6 (Phase 9). Alternatives: per-channel counters, sequence allocation later |
| R-002 | Outbox relay not implemented: events accumulate with `published_at IS NULL`                                                          | Medium | Implement relay + retention (Phase 2/3); live screens use NOTIFY meanwhile                                     |
| R-003 | HS256 shared-secret JWT, no MFA, no refresh/rotation                                                                                 | High   | Move to OIDC provider with asymmetric keys + MFA for privileged roles before any real deployment (ADR-0009)    |
| R-004 | Cross-tenant background jobs vs RLS                                                                                                  | Medium | Design a worker role with audited BYPASSRLS or per-tenant iteration; ADR before relay                          |
| R-005 | Legal/tax/payroll/food-safety rules are unverified                                                                                   | High   | All such logic labelled unverified; specialist review list in `docs/compliance/assumptions.md`                 |
| R-006 | No offline operation yet; WAN loss stops ordering                                                                                    | High   | Phase 6 store-edge runtime; schema already carries store sequences and inbox                                   |
| R-007 | Rate limiting is in-process (per replica)                                                                                            | Medium | Redis-backed limiter (Redis already in compose)                                                                |
| R-008 | `idempotency_keys` and `outbox_events` grow without bound                                                                            | Low    | Retention jobs + partitioning by month                                                                         |
| R-009 | Generated DB types can drift from migrations                                                                                         | Low    | CI job: migrate fresh DB, run codegen, fail on diff                                                            |
| R-010 | Request logs include full headers (authorization is redacted)                                                                        | Low    | Trim pino-http serializers; review PII in logs                                                                 |
| R-012 | Taking payment is gated by `orders.create`; no till/drawer session ties cash to a person and drawer yet                              | Medium | Till sessions + a dedicated payments permission in Phase 3                                                     |
| R-013 | Supervisors (discount.approve) can comp orders up to 100% without a second person                                                    | Medium | Consider a separate discount.comp permission or cap; review comp reports                                       |
| R-014 | Account-level failure throttling lets an attacker temporarily lock out a known approver (DoS)                                        | Low    | Accepted trade-off vs brute force; move limiter to Redis with alerting (R-007)                                 |
| R-011 | Guest order token in URL grants view of that order                                                                                   | Low    | 128-bit random; contains no PII beyond the given first name; consider expiry                                   |
